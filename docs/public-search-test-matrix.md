# Public catalog search acceptance (#197)

The public reader uses PostgreSQL native tsvector/GIN and SQLite FTS5. It never filters a full catalog in JavaScript. Anonymous matching alone reads at most 500 sanitized analyses. The PostgreSQL role can select only the catalog/search views and execute only `consume_public_search_quota(integer)` and `search_public_catalog(tsquery)`. Source visibility and current analysis identity are rechecked in the live view for every read. A security-definer search function places the full-text predicate next to the GIN-indexed sanitized document while rechecking live catalog membership; the outer security-barrier view still controls projection. The bounded server response cache lives for 60 seconds and facets for five minutes; both are keyed by live visibility generation and current visible row count, including expiry. The cache validator hashes the current response; `max-age=0, must-revalidate` prevents serving an opted-out source from an unvalidated HTTP cache. Match responses are always `no-store`.

## Local acceptance evidence (2026-10-07)

The final database/HTTP/SEO suite passed all eight tests on Node 26.10.0. With 10,000 rows and 25 sequential warm queries, SQLite endpoint p95 was 5.21 ms and PostgreSQL p95 was 41.47 ms. The first cold PostgreSQL endpoint took 869.72 ms across multiple statements; its slowest individual statement was 317.86 ms. The actual separate public reader connection reported `statement_timeout = 500ms`, and its queries succeeded. These measurements establish the warm-cache target, not a sub-100 ms cold-endpoint guarantee.

Served Chromium testing against the migrated native application PostgreSQL database passed at 390 × 844: homepage, search, detail, company, and skill pages returned 200 with no horizontal overflow, private sentinel text, or browser errors. Keyword submission returned the single expected TypeScript fixture. Served HTTP checks covered invalid-query 400, unchanged ETag 304, anonymous match `no-store` and zero model calls, OpenSearch/robots/sitemap, and immediate source opt-out removing search results, detail, and sitemap entries. Fixture rows were created through native source analysis publication. Local asset/secrets readiness used fixture overrides; this does not verify production provider readiness or Google rich-result acceptance.

`apps/site/scripts/public-site-browser-smoke.mjs` repeats the mobile checks against a seeded server. Set `PUBLIC_SITE_URL`, `PUBLIC_SITE_EVIDENCE_DIR`, `PUBLIC_SITE_FIXTURE` (JSON containing three fixture `ids` and a `companyId`, with the TypeScript fixture first), and optionally `PUBLIC_SITE_CHROME`. The fixture should contain one TypeScript role, one PostgreSQL role, and one Rust role at the same company. The script records screenshots and browser findings; it does not create or modify catalog data. Session evidence is under `/tmp/agent-first-release/search-evidence/` (`final.log`, `benchmark-*.json`, `mobile-results.json`, `served-http-results.json`, and `ui-check.log`). Svelte check reported zero errors and zero warnings.

Public HTML pages use `private, no-store`: their global layout can include account/session state. Only the anonymous REST and XML/text discovery responses use public revalidation headers. The sanitized database cache remains shared independently of HTML caching.

The P5 mobile follow-up replaces the enabled catalog homepage's full-screen invite card with a compact search header, bounded native skill typeahead, and latest listings above the 844px viewport fold. Disabled catalog and private deployment behavior is preserved. Homepage and search pages expose an anonymous matching panel: local skill selection, explicit POST submission, no storage/analytics, strict schema validation, coverage/missing/unknown explanations, and zero model calls. Clearing/changing submitted skills aborts pending requests and invalidates their generation so stale responses cannot restore results. The browser smoke now exercises Enter-key skill addition and submission, actual native-database matching, above-fold listing position, and delayed-response clearing. `p5-browser-final.log`, `mobile-home.png`, and `mobile-match-panel.png` record the passing 390px mobile run; `p5-unit.log` passes 14 tests and `p5-check.log` reports zero errors/warnings.
