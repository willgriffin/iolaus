# Daily-use release qualification

Tracking: https://github.com/willgriffin/iolaus/issues/164.

This integration release collects previously local daily-use development. It
includes private hosted workspaces and MCP integration, source intake and
scheduling, evidence-backed opportunity assessment and screening questions,
skill discovery, mobile administration and resume editing, and indexed current
recommendation sorting. Individual issue closure is determined from verified
completion; this record does not declare unfinished work complete.

## Delivery and data boundaries

The release candidate is validated separately from the active daily-use app.
Provider keys, personal databases, local runtime state, generated knowledge,
browser artifacts and temporary operational receipts are not release inputs.
The generated root virtual-module declaration is excluded. The one-off reset
utility pinned to a specifically named local fresh-clone database and its tests
are retained locally rather than included as public application functionality;
no reset is executed by this release. Existing assessment
history and human review/application records must survive migrations and
backfill. Index/rank backfill reuses verified results without provider calls.

Risk is high because this release changes private authorization boundaries,
persistent assessment publication, and database-backed ranking. Independent
review must cover the final committed candidate, with any accepted fixes
retested and reviewed before publication. CI image and browser checks remain
publication gates; local success does not replace them.

## Qualification matrix

| Behavior | Evidence required |
| --- | --- |
| Portable dependency closure | Fresh frozen-lockfile install; container dependency stage includes all local package and patch inputs; CLI validator positive/negative checks |
| Private hosted workflows and MCP | Native principal, cross-tenant/user/profile deny cases, ownership and revocation tests; synthetic browser/MCP fixtures |
| JEV screening and skill discovery | Current typed contracts, exact citation/provenance checks, primary-versus-introductory skill semantics, stale/malformed input and retry tests |
| Atomic assessment and rank publication | Native transaction affinity, rollback/concurrency/recovery tests on supported databases; migration and index validation |
| Recommendation sorting | Badge-value parity, global ordering before pagination, stable ties/unknown placement, stale and foreign record cases; PostgreSQL query plan and before/after timings |
| Source and task workflows | Bounded intake, native queue/schedule, source provenance and activity tests |
| Mobile administration and resume UI | Component and browser tests for navigation, triage, selection, preferences, resume editing and dark/mobile presentation |
| Build/runtime qualification | Repository format, lint, check, tests, build and strict domain-knowledge freshness; immutable candidate parity and runtime checks in CI |
| Existing data preservation | Bounded zero-AI backfill receipt and checks for unchanged profile, source, human review, application and decision records |

Detailed behavioral matrices live alongside the relevant features in `docs/`.
Validation artifacts, final review identity and exact commit/check results are
recorded on the tracking issue and release pull request. A check not yet run is
pending, not implicitly passed.
